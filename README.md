## โครงสร้างระบบ

```text
ผู้ใช้งาน
  → GitHub Pages (docs.html)
  → Google Apps Script Web App
  → Google Sheets / Google Drive
```

GitHub Pages ทำหน้าที่เป็นหน้าเปิดระบบและฝัง Web App ผ่าน iframe ส่วนการจัดการข้อมูล การแนบรูป การจัดทำเอกสาร และการพิมพ์ ทำงานใน Google Apps Script

การ deploy ปัจจุบันจำกัดสิทธิ์เป็น **เจ้าของ Apps Script เท่านั้น** และหน้า GitHub Pages เปิดระบบเป็นแท็บใหม่แทน iframe เพื่อป้องกันการฝังหน้าเอกสารในเว็บไซต์อื่น หากต้องการเปิดใช้กับบุคคลเพิ่มเติม ให้กำหนดสิทธิ์ของ Google Apps Script และการยืนยันตัวตนให้ชัดเจนก่อนปรับค่า `webapp.access`.

## การแก้ไขระบบหลัก

ซอร์สของ Google Apps Script ถูกเก็บไว้ในโฟลเดอร์ `apps-script/` และซิงก์กับ Script ID `1X9EndGiZflGWzCGg2kVRdnIs5uZXbsO5NEpRjryTUivW45Fk6vFRGV0K` ผ่าน `clasp`:

```text
apps-script/
├─ รหัส.js
├─ legal-doc-system.html
└─ appsscript.json
```

ห้ามเก็บรหัสผ่าน, API key, token หรือข้อมูลส่วนบุคคลใน GitHub ให้ใช้ Script Properties หรือการตั้งค่าที่ Google Apps Script จัดการแทน

ไฟล์ `.clasp.json` เป็นการตั้งค่าเฉพาะเครื่องและต้องไม่ commit แม้มีเพียง Script ID. Endpoint `doPost` ภายนอกถูกปิดไว้ เพราะ endpoint เดิมเข้าถึงแบบ anonymous และใช้ shared key ที่อยู่ในซอร์ส ซึ่งเสี่ยงต่อการใช้ Gemini quota และการอัปโหลดข้อมูลโดยไม่ได้รับอนุญาต.

## ขั้นตอนอัปเดตอย่างปลอดภัย

1. ดึง/สำรองซอร์สจาก Google Apps Script ก่อนแก้ไข
2. แก้ไขและทดสอบในหน้า Web App โดยเฉพาะมือถือแนวตั้งและแนวนอน
3. อัปโหลดซอร์สด้วย `clasp push` แล้วตรวจทานที่ Apps Script
4. สร้างเวอร์ชันและ Deploy ใหม่จาก Google Apps Script เมื่อตรวจรับแล้ว
5. หาก URL `/exec` เปลี่ยน ให้แก้ `src` ใน `docs.html`
6. Commit และ Push ไฟล์ที่เกี่ยวข้องขึ้น GitHub
7. เปิด GitHub Pages เพื่อตรวจการใช้งานจริงอีกครั้ง

## การปรับปรุงในชุดโค้ดนี้

- มีแถบปุ่ม **แนบรูปภาพ** และ **จัดทำเอกสาร** ทั้งในหน้าและแบบลอย โดยปุ่มจัดทำเอกสารจะพร้อมใช้เมื่อเลือกคดีแล้ว
- รองรับมือถือแนวตั้ง/แนวนอน พร้อมตารางคดีแบบการ์ดบนจอแคบ
- รายงานประจำเดือนเลือกและเปิดข้อมูลรายวันผ่านปฏิทิน: วันที่บันทึกแล้วเป็นสีเข้ม ข้อมูลที่แก้ไขแต่ยังไม่บันทึกเป็นสีเหลืองอ่อน และวันที่ว่างเป็นสีจาง
- เก็บและรวมยอดแยกตามเลขบัลลังก์/ห้องพิจารณาคดี โดยเลขบัลลังก์จากคอลัมน์ E ของชีตไม่ถูกส่งไปพิมพ์ในรายงานกระบวน

## รายงานประจำเดือน: ลำดับการทำงาน

1. เลือกเดือน/ปี และกดวันที่จากปฏิทิน
2. เลือกคดีออนไลน์ของวันนั้นจากข้อมูลที่โหลดจากชีต (ถ้ามี)
3. ติ๊กผลการดำเนินงานของแต่ละคดีได้มากกว่าหนึ่งรายการ
4. ตรวจยอดแยกตามห้องพิจารณาคดี
5. บันทึกรายงานของวันที่เลือก
6. แนบไฟล์สำนวนส่งคืนเพื่อออกแดง และติ๊กเฉพาะเลขคดีที่ต้องนับ

ปฏิทินแสดงสถานะรายวัน: สีน้ำเงินเข้มคือบันทึกแล้ว, สีเหลืองคือมีการแก้ไขที่ยังไม่บันทึก, และสีจางคือยังไม่มีข้อมูล

### สำนวนส่งคืนเพื่อออกแดง

- กดโหลดรายการคดีทั้งหมดจากชีตก่อน แล้วค้นหาและติ๊กเลือกได้หลายคดี
- ระบบเพิ่มยอดเฉพาะคดีที่ติ๊กเลือกเข้า “แล้วเสร็จโดยเข้าศูนย์ไกล่เกลี่ย” ตามห้องพิจารณาคดีของแต่ละคดี
- คดีเก่าที่ไม่มีในชีตต้องเพิ่มเลขคดีและห้องพิจารณาคดีเอง แล้วจึงเลือกนับได้
- ไฟล์ที่รองรับคือ PDF, รูปภาพ, Word และ Excel ขนาดไม่เกิน 8 MB ต่อไฟล์ ไฟล์เก็บใน Google Drive เมื่อกดบันทึกรายงาน
- ยอดจากสำนวนส่งคืนเป็นส่วนหนึ่งของยอดไกล่เกลี่ย ไม่ใช่ยอดใหม่ที่นับซ้ำ

### การเปิดรายงานรายเดือนและโหลดคดีจากชีต

- ปุ่ม **เปิดรายงานที่บันทึก** ใช้เปิดเฉพาะรายงานรายเดือนที่เคยกดบันทึกในระบบแล้ว โดยเลือกเดือนและปี พ.ศ. ให้ตรงกัน
- ปุ่ม **โหลดรายการคดีจากชีต** ใช้ดึงเลขคดีจาก Google Sheet มาให้เลือกในขั้นตอนที่ 2 และใช้กับรายการสำนวนส่งคืนเพื่อออกแดงได้ทันที
- หากยังไม่เคยบันทึกรายงานของเดือนนั้น ระบบจะแจ้งชัดเจนและไม่ล้างข้อมูลที่กำลังกรอกอยู่
- รายงานเก่าที่หัวรายงานเป็นเดือนหนึ่ง แต่เก็บวันที่อยู่คนละเดือน ระบบจะย้ายเฉพาะ "วัน" เดิมมาอยู่ในเดือน/ปีของหัวรายงานอัตโนมัติ เช่น `2026-06-16` ในรายงานเดือนสิงหาคม 2569 จะแสดงเป็น `2026-08-16` โดยยอดคดีไม่เปลี่ยน
- ชีตต้นทางปัจจุบันไม่มีคอลัมน์วันที่รายงาน จึงไม่สามารถแยกคดีเข้าวันในปฏิทินโดยอัตโนมัติได้ ผู้ใช้เลือกวันรายงานก่อน แล้วจึงเลือกคดีที่ต้องการนับ
- หากต้องการกรองคดีเข้าวันที่อัตโนมัติในอนาคต ให้เพิ่มคอลัมน์ **วันที่รายงาน** ในชีตเป็นวันที่จริง เช่น `2026-08-02`
