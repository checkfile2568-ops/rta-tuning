# My Music Library — Functional audit — 21 Nov 2026

## Scope and evidence

Reviewed the current `music/index.html` source on `main`, plus `firebase-config.js` and `passkey-config.js`. The web app is hosted on GitHub Pages. This audit distinguishes static checks and mocked browser-event simulations from real-device end-to-end checks.

### Verified from code

- JavaScript inline scripts: all 5 parsed successfully after the changes.
- Functional simulated scenarios with a fake document/DOM, localStorage, browser prompts and fake URL parsing:
  - Initial local library loaded 5 seed songs.
  - Create and rename Playlist.
  - Add a new valid YouTube link into the selected Playlist; it appeared once in the library and once in the Playlist.
  - Delete the Playlist while preserving its song in the master library.
  - Add an existing song to a Playlist and reject a duplicate.
  - Edit a song's name and category.
  - Remove a song from a Playlist without deleting it from the master library.
  - Delete the master-library song when explicitly operating in master-library view.
  - Volume slider 37 produced text 37%.
  - Keyword search opened the correct YouTube search-results URL.
- Added a responsive Glassy 3D volume block with numerical output, initial value 90%, 0–100% range, accessible value and 3D slider thumb.
- Song list now renders in blocks of 60 and has a load-more control to prevent long DOM builds.

### Remaining concerns and limitations

- No hardware/browser audio test: cannot independently verify actual sound quality, autoplay, seek performance, or volume behavior on iOS/Android.
- Browser/OS may ignore volume changes for certain embedded players. Slider number mirrors commands sent to YouTube, not an independently measured output gain.
- YouTube IFrame Player is the source; app does not extract/re-encode audio, but YouTube chooses stream quality.
- GitHub Pages public URL could not be inspected through current web retrieval. Source commit is verified, remote publishing and browser execution are not.
- YouTube search is a handoff to YouTube, not an in-app result-grid integration.
- Firebase web configuration is still null; Passkey API is disabled. Cross-device and private server-side Playlist syncing remain unavailable.
- Local PIN is a per-browser screen gate, not cross-device or back-end authentication.
- Playlist CRUD saves in localStorage; long-term resilience requires exports, especially before clearing browser data.
- Screen Wake Lock cannot guarantee display stays on and does not permit playback with the phone locked.
- This is a mocked UI-flow audit, not an automated real-browser end-to-end regression suite.

## Release criteria for complete sign-off

1. Test PIN creation, unlock, wrong code, session restoration and browser storage clearing on Android Chrome and iOS Safari.
2. Test video playback/seek/volume, ads, blocked embedding, YouTube error responses, pause/skip/shuffle/repeat.
3. Test add/rename/delete/import/export with 1, 60, 500 and 2000 songs and changing device orientation.
4. Test disabled/local and connected/cloud states separately; configure protected synchronization before claiming cross-device support.
5. Keep all earlier songs and playlists intact; export a backup before any future migration.
