# ค้นหาเหตุการณ์จากข้อความและส่งออกพร้อมซูม

หน้าเดิม: `video-studio-v5.html` (เมนู `video` ใน MMs)

เลือกวิดีโอ → พิมพ์ “ไฮไลท์ยิงประตู” / “ผู้เล่นเจ็บ” → วิเคราะห์และแบ่งช่วงเวลา → ตรวจผลและแก้เวลา → ตัดคลิปหรือบันทึกภาพเหตุการณ์

- อ่านภาพต้นฉบับเต็มเฟรมทุก 1, 2 หรือ 4 วินาที ชุดละไม่เกิน 24 ภาพ มีภาพคาบเกี่ยวระหว่างชุด
- วิเคราะห์ได้ทั้งวิดีโอหรือเฉพาะช่วงที่เลือก และหยุดโดยเก็บผลที่ได้แล้ว
- เวลาท้องถิ่นของแต่ละ Part แปลงเป็นเวลารวม; ช่วงก่อน/หลังใช้ค่าที่ตั้งไว้
- AI เสนอเหตุการณ์ให้ตรวจ ไม่ยืนยันว่าลูกเข้าประตูหรือวินิจฉัยอาการเจ็บ ไม่มีการวิเคราะห์เสียง อาจพลาดเหตุการณ์ระหว่างภาพ
- ไม่เปลี่ยน zoom / center / enhancement เดิม ภาพนิ่ง PNG และคลิป MP4 ใช้ FFmpeg filter ตัวเดียวกัน
- ปุ่ม JSON เก็บช่วงเวลาพร้อมค่าซูมลงอุปกรณ์; ผล AI ชุดนี้ไม่ถูกบันทึกประวัติอัตโนมัติ
- ต้องเปิดหน้าไว้ระหว่างสแกน คลิปยาวใช้เวลาตามจำนวนภาพและโควตา Gemini; ลิงก์ต้นทางหมดอายุให้โหลดวิดีโอใหม่

## การเชื่อมต่อ

เพิ่ม `video-events` ใน `mms-gemini-api` โดยคง actions เดิมและ `verify_jwt=true` ตรวจ MMs session, เจ้าของไฟล์, สถานะวิดีโอ และจำนวน/ขนาดภาพก่อนเรียก Gemini ใช้ GEMINI_API_KEY / GEMINI_MODEL เดิม ไม่เพิ่มคีย์ในหน้าเว็บ ไม่เปลี่ยนฐานข้อมูลหรือสิทธิ์เมนู

## การตรวจสอบ

- `node --test tests/video-events*.test.mjs`: 8 tests, รวมเวลา Part, ข้อมูล AI ผิดรูปแบบ, merge, การเลือก Part และ denial paths ของ API ด้วย mock
- browser QA ใช้วิดีโอสีทดสอบ 6 วินาทีและผล AI จำลอง: สแกนภาพจริง, แก้เวลา, คง zoom 2x, ส่งออก PNG และ MP4 5 วินาทีสำเร็จ
- Native FFmpeg ทดสอบ filter ซูม 2x จาก 640×360 ได้ภาพ 320×180
- ไม่มีการวัด precision/recall กับการแข่งขันจริง และไม่ได้ใช้ session ของผู้ใช้ทดสอบ inference จริง

## ย้อนกลับ

ใช้ `git revert` กับ commit ที่เพิ่มฟีเจอร์นี้แล้วเผยแพร่ GitHub Pages ใหม่ หากต้องย้อน backend ด้วย ให้นำ source ของ `mms-gemini-api/index.ts` ใน commit นี้ ลบบล็อก `video-events` และฟิลด์ capabilities `video_events` แล้ว deploy ด้วย verify_jwt=true (เทียบเท่า v2 ก่อนปรับปรุง)

## ตรวจซูม/ความคมชัดและภาพช้า (29 ตุลาคม 2569)

- ซูมและ unsharp มีผลจริงในไฟล์ส่งออก เดิมวิดีโอตัวอย่างแสดงเพียงกรอบซูมและ CSS แสงสี จึงเพิ่มปุ่ม “ดูผลซูมและความคมชัดจริง ณ เฟรมนี้” สร้าง PNG ด้วย FFmpeg filter เดียวกับไฟล์ส่งออก แสดงเวลาและค่าที่ใช้ พร้อมแจ้งเมื่อปรับค่าแล้วภาพตัวอย่างยังไม่อัปเดต
- เลือกความเร็วปกติ 1× / ช้า 0.5× / ช้ามาก 0.25× ใช้ทั้งการเล่นวิดีโอและส่งออกด้วย “ตัดในเครื่อง” เวลาเหตุการณ์ยังอ้างอิงต้นฉบับ และคำนวณความยาวผลลัพธ์ตามอัตราที่เลือก
- ภาพช้าใช้ setpts และเสียงใช้ atempo เพื่อรักษาระดับเสียง รองรับไฟล์มีเสียง ไม่มีเสียง และเลือกตัดเสียง เมื่อเลือกภาพช้าจะไม่ให้ส่งคิวเซิร์ฟเวอร์ เพราะ Worker รุ่นที่ติดตั้งยังไม่รองรับอัตรานี้
- ไม่เปลี่ยนส่วนซูมของ Worker ในรอบนี้ การทดสอบไฟล์จริงและผลเทียบพิกเซลในรอบนี้ครอบคลุมการส่งออกในเบราว์เซอร์
- `node --test tests/video-*.test.mjs`: 10 tests รวม native FFmpeg integration; ไฟล์ช่วง 2 วินาทีส่งออกเป็น 2 / 4 / 8 วินาทีตามอัตรา และเสียงยาวตรงกับภาพ
- ทดสอบตำแหน่ง crop ที่ center=(0.25,0.75), zoom=2 เทียบพิกเซลกับ crop=160:90:0:90 ตรงกัน; ขนาดต้นฉบับ 320×180 กลายเป็น 160×90
- ความคมชัด 0 กับ 100 ให้ค่าเฉลี่ยส่วนต่างพิกเซล 1.532 ระดับ และความต่างขอบภาพเพิ่มขึ้นบนวิดีโอทดสอบ (ไม่ได้เพิ่มรายละเอียดที่ต้นฉบับไม่มี)

- Browser QA เพิ่มเติม: วิดีโอทดสอบมีเสียง 6 วินาที ซูม 2× ความคมชัด 80 ส่งออกจริงด้วย FFmpeg-WASM สำเร็จที่ 0.5× (12 วินาที) และ 0.25× (24 วินาที); แสดงภาพ PNG ที่ประมวลผลจริงสำเร็จ และปุ่มคิวเซิร์ฟเวอร์ถูกปิดเมื่อเลือกภาพช้า

## แก้มือถือถูกบังและเลิกใช้คิว (29 ตุลาคม 2569)

- หน้าตัดวิดีโอใช้การดาวน์โหลดตรงเท่านั้น เอาแท็บคิวเซิร์ฟเวอร์และการเช็ก Worker ออก ไม่สร้าง video_export job จากหน้านี้
- เปลี่ยนหัว Video Studio เป็น static และย่อหัวบนมือถือ ขณะเปิด workspace ซ่อน hero/การ์ดเมนู ให้ iframe ใช้พื้นที่ที่เหลือเต็ม; กดปิดจึงกลับเมนู
- โหมดเริ่มต้น “เร็ว (ไม่เกิน 720p)” ไม่ขยายภาพเล็กขึ้น ใช้ ultrafast; ยังเลือกความละเอียดต้นฉบับและคุณภาพอื่นได้
- ภาพช้าลด FPS ตามอัตราเวลาแทนการเข้ารหัสเฟรมซ้ำจำนวนมาก รักษาความยาวและเสียงให้ตรงกัน การทดสอบช่วงต้นฉบับ 2 วินาที 24fps ใช้เฟรมวิดีโอไม่เกิน 50 เฟรมทั้ง 0.5× และ 0.25× และได้ความยาว 4 / 8 วินาที
- ใช้ต้นทางหนึ่ง Part ที่อ่านแล้วซ้ำได้ระหว่างดูภาพจริง/ตัดอีกช่วง โดยเก็บใน FFmpeg เพียงหนึ่ง cache; เปลี่ยนต้นทางหรือกดหยุดจะยกเลิก/แทน cache เดิม
- เพิ่มปุ่มหยุดการตัด ซึ่ง abort การดาวน์โหลดและ terminate FFmpeg ได้ แล้วเริ่มตัดใหม่ได้
- ต้นทางขนาดใหญ่ยังต้องอ่านทั้ง Part ครั้งแรก ระยะเวลาขึ้นกับขนาดไฟล์ อินเทอร์เน็ตและกำลังเครื่อง ไม่ได้อ้างว่าเป็น instant export
- ทดสอบ `node --test tests/video-*.test.mjs`: 12 ผ่าน รวม cache reuse/eviction, abort/retry และ native FFmpeg พร้อมเสียง ภาพช้า ซูม และความคมชัด
- Browser QA ใช้ shell + iframe ที่กว้าง 344px และวิดีโอทดสอบจริง: หัวสูงประมาณ 63px เป็น static เลื่อนพ้นปุ่มได้, ยกเลิกระหว่างเตรียม FFmpeg แล้วตัดใหม่สำเร็จ, 0.25× พร้อม zoom=2/sharpness=60 ได้ MP4 24 วินาที
- ยกเลิกงาน queued ของ video ที่ตรวจพบตรงกับยอด 5 งานในภาพผู้ใช้; ตรวจซ้ำเหลือ active video jobs = 0 (เป็นการเปลี่ยนสถานะ cancelled ไม่ใช่ลบไฟล์)
