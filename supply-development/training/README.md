# พื้นที่ฝึกระบบเบิกวัสดุ — รุ่น 1.2.0

ติดตั้ง API รุ่น 1.2.0 เป็น Apps Script deployment version 4 วันที่ 7 พฤศจิกายน 2569 โดยคง URL เดิมและสิทธิ์เข้าถึงเดิม หน้าเว็บใช้ asset version 1.2.0 ตรวจสถานะ GitHub Pages ของ commit ที่เผยแพร่ก่อนเข้าใช้งาน

## การใช้งานหลังติดตั้ง

1. แอดมินเปิดเมนู **ทดลองใช้งาน** กด **สร้างข้อมูลตัวอย่าง 10 รายการ** และยืนยัน
2. เจ้าหน้าที่พัสดุเปิดเมนูเดียวกันจากเครื่องใดก็ได้ กด **เข้าพื้นที่ฝึก**
3. มีคลังตัวอย่าง 10 รายการ รับเข้า 1 ใบ รอจัดเตรียม 1 ใบ และพร้อมรับ 1 ใบ
4. ลองรับเข้าเพิ่ม เบิก จัดเตรียม ส่งมอบ รับคืน ตรวจนับ และดูสถิติ/กระทบยอด
5. กด **กลับคลังจริง** เพื่อออกจากการฝึก
6. แอดมินกด **ล้างชุดฝึก** เมื่อจบรอบ แล้วสร้างใหม่เพื่อเริ่มต้นอีกครั้ง

การล้างปิดการใช้งานชุดเดิมและเก็บ Spreadsheet เดิมไว้กู้คืน ไม่ลบถาวร ไม่ล้างบัญชีหรือคลังจริง แท็บที่ยังเปิดชุดเดิมจะถูกปฏิเสธเมื่อพยายามบันทึก ไม่มีการสลับไปเขียนข้อมูลจริงอัตโนมัติ

## ขอบเขตการแยกข้อมูล

- Authentication และสิทธิ์ตรวจจากฐานจริงก่อนเลือกชุดฝึก ไม่มีบัญชีหรือ PIN ทดสอบเพิ่ม
- ชุดฝึกใช้ Spreadsheet ใหม่ร่วมกันผ่าน API เดิม ไม่คัดลอกคำขอหรือสต๊อกจริง
- แยก catalog, dashboard cache, OP_UUID, INFLIGHT, REPAIRS และเวอร์ชันจากระบบจริง
- ตะกร้า/ร่าง/คิวส่งในเครื่องแยกตามบัญชีและ generation และปฏิเสธส่งข้ามพื้นที่
- แอดมินเท่านั้นที่สร้าง/ล้าง เจ้าหน้าที่ทำงานตามสิทธิ์เดิม ไม่แปลง session แอดมินเป็นเจ้าหน้าที่
- ไม่เปิดให้แก้บัญชี PIN สิทธิ์ โปรไฟล์ สำรองข้อมูล หรือการตั้งค่าจริงผ่านพื้นที่ฝึก
- ไม่ส่ง LINE ในพื้นที่ฝึก เอกสารพิมพ์มีคำเตือน **ข้อมูลตัวอย่าง ห้ามใช้เบิกจ่ายจริง**
- Audit การสร้าง/ล้างอยู่ในระบบจริงเพื่อระบุผู้ดำเนินการ ส่วนธุรกรรมฝึกอยู่ในฐานฝึก

## ลำดับติดตั้งครั้งแรก / ดูแลรุ่นถัดไป

1. เปิด Apps Script โครงการเดิมและส่งออก source **ปัจจุบันจริง** เก็บสำเนาพร้อม deployment version ก่อนแก้
2. ใช้ `integrate.py current-Code.gs patched-Code.gs` กับ source ที่เพิ่งอ่านเท่านั้น ห้ามใช้ reference backend เก่าแทน source ล่าสุด
3. ตัว patcher ตรวจจำนวนจุดเชื่อมต่อและหยุดเมื่อ source ไม่ตรง ต้องตรวจ diff และปรับเฉพาะจุดให้เข้ากับ source จริง
4. เพิ่ม `Training.gs` และใส่ hooks ในโครงการเดิม ตรวจ Syntax และทดสอบ denied paths
5. อัปเดต deployment เดิมเป็นเวอร์ชันใหม่ โดยคง URL และการเข้าถึงเดิม ไม่มีการเปลี่ยน sharing ของ API หรือฐานจริง
6. ทดสอบ `training.status`/สิทธิ์ จากนั้น deploy frontend ใน branch นี้ไป main จึงเปิดใช้ปุ่ม
7. แอดมินสร้างชุดจริง 1 ครั้ง ทดสอบพัสดุรับเข้า–จ่าย–รับคืนและกระทบยอดในพื้นที่ฝึก พร้อมยืนยันว่ายอดจริงเดิมไม่เปลี่ยน
8. ล้างชุดฝึก ทดสอบแท็บเก่าบันทึกไม่ได้ แล้วสร้างอีกครั้งเพื่อส่งให้เจ้าหน้าที่ทดลอง

อ่าน source Apps Script ปัจจุบันจริง รุ่น 1.1.3 ก่อนแก้แล้ว (SHA-256 `2ac7e94c62956182cc2d4a7ac94f1eae106410e8dbe611914468c070ce00069b`) และติดตั้ง hooks พร้อม Training.gs รวมในไฟล์รหัส.gs เดิม รุ่น 1.2.0 ผู้ติดตั้งสร้างชุดเริ่มต้นผ่านคำสั่ง editor-only `installTrainingExample` โดยบันทึก actor เป็น `EDITOR_OWNER` ไม่สวมชื่อบัญชีผู้ใช้ในระบบ คำสั่ง `archiveTrainingExample` ปิดชุดฝึกและเก็บสำเนาไว้ คำสั่งทั้งสองไม่อยู่ใน API routes และใช้จากตัวแก้ไขที่เจ้าของโครงการเข้าถึงได้เท่านั้น

## การทดสอบที่ทำแล้ว

Backend จำลอง 7 กรณี และ frontend/DOM 4 กรณี ผ่านทั้งหมด ทดสอบซ้ำกับ source Apps Script รุ่น 1.1.3 ที่อ่านจากตัวแก้ไขจริงแล้ว ทดสอบสิทธิ์ สร้างซ้ำ แปลงหน่วย กระทบยอด จ่าย/คืน ล้าง/เปลี่ยนชุด การไม่เขียนสต๊อกจริง และการแยกข้อมูลในเครื่อง

ตรวจผ่าน API จริงแล้ว: login เจ้าหน้าที่พัสดุ, ห้ามเจ้าหน้าที่สร้างชุดฝึก, คลังตัวอย่าง 10 รายการ, ใบรับเข้า 6,811 บาท, จัดเตรียม–จ่าย–รับคืน, กระทบยอด และ hash รายการวัสดุจริง 5 รายการก่อน/หลังไม่เปลี่ยน การทดสอบปุ่มแอดมินเป็น DOM จำลอง ส่วนคำสั่งสร้าง/ล้างตรวจผ่าน editor-owner ไม่ใช่การคลิกปุ่มด้วย session แอดมินจริง

ทดสอบซ้ำกับ source ล่าสุดก่อน deploy:

```sh
mkdir -p test-gas
python integrate.py current-Code.gs test-gas/Code.gs
cp Training.gs test-gas/Training.gs
GAS_TEST_DIR="$PWD/test-gas" node --test tests/training.test.cjs
npm install
WEB_ROOT=/path/to/repo/supply node --test tests/frontend.test.cjs
```
